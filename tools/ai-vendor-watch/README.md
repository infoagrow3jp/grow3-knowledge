# ai-vendor-watch

Anthropic・OpenAI・Google の公式の更新情報を集め、使い方スキル（`claude-usage`／`gpt-usage`／`gemini-usage`）を更新し続けるための道具。

| ファイル | 役割 |
|---|---|
| `sources.yaml` | 監視ソースの定義（提供元・取得先・日付の取り方・重点ページ）。提供元を足すときはここに足す |
| `collect.py` | 収集。LLMを使わない。日付順ログ（各スキルの `references/changelog/YYYY-MM.md`）と `state/items.json` に追記する |
| `check_skill.py` | スキルの機械検査（5点） |
| `run.py` | 毎日の実行本体。照合 → 収集 → モデルの見張り → 判定・反映 → 検査 → 公開 → 呼び出し設定の見直し |
| `model_watch.py` | 使っているモデルの廃止・互換性の変更だけを見張る（`mode: watch_models` の提供元） |
| `state/items.json` | 項目ごとの状態。公開先（origin/main）の実態の写し |

## 提供元ごとの動かし方（`sources.yaml` の `vendors.<提供元>.mode`。2026-11-23〜）

| 提供元 | mode | 動き |
|---|---|---|
| Anthropic（claude-usage） | active | 収集と自動更新を続ける。判定では、呼び出しの失敗・廃止への対応・有効な使い方の改善につながる情報を優先する |
| OpenAI（gpt-usage） | watch_models | 定期の収集と自動更新を止める。このPCで実際に使っているモデル（設定ファイルと実行記録から毎回読む）が、公式の廃止予定の表・Codex のモデルのページの廃止の節・API の変更履歴に出たときだけ、失敗として知らせる（同じものは1回。廃止日の30日前にもう1回） |
| Google（gemini-usage） | paused | 定期の収集と自動更新を止める |

止めた提供元も、スキル・ログ・状態のファイルは消さない。止める前に集めた「判定待ち」の項目は、そのまま残る（処理しない）。再開するときは mode を active に戻す。

## 役割の分担

- **日付順ログ**は事実の記録で、自動追記だけ。公式の見出し・バージョン・日付・出典を1件ずつ、新しい順に書く。
- **スキル本体**は「今どう使うか」。ログをそのまま貼らない。根拠のない一般論を書かない。
- 初版のスキルは現行の公式ドキュメント（各スキルの `references/sources.md` の重点ページ）から書いた。初回に取り込んだ過去の更新は、個別には反映していない。

## 項目の状態

| 状態 | 意味 |
|---|---|
| 判定待ち | 影響の有無を機械的に決められなかった |
| 反映待ち | 影響ありと判定され、スキルへの反映が公開先に届いていない |
| 反映済み | 反映を含むコミットが公開先にある |
| 対象外 | 影響なしと判定された |
| 確認保留 | 公開先を取得できず、反映済みかどうか判断できない |

「反映済み」の正は、コミットメッセージ末尾の `Vendor-Watch-Items: <ID>, <ID>` が公開先にあるかどうか。`items.json` はその写し。

## 判定と反映の決まり

`run.py` が起動したAIは、渡された項目について次のとおりにする。

### 判定

- 基準は一つ：**その更新を知らずに呼ぶと、呼び出しが失敗するか、結果が明らかに悪くなるか**。当たれば「反映」、当たらなければ「対象外」。
- 優先するのは、呼び出しの失敗・廃止への対応・有効な使い方の改善につながる情報（2026-11-23〜）。
- 「反映」に当たる例：既定のモデル・オプションの廃止や改名、非対話実行の指定の変更、権限・承認の既定の変更、指示ファイルやスキルの読み込み方の変更、公式のプロンプトの書き方の変更、モデルの廃止と移行先。
- 「対象外」の例：料金・プラン・地域展開・企業向け管理機能だけの更新、画面だけの変更、呼び方に関わらない記事。
- 知っていると便利な程度の新機能は、`references/details.md` にだけ書く「反映」としてよい。迷ったら details.md に置く。
- 原文の抜粋で決めきれないときは出典を読む。読めなければ「反映」にせず、理由に読めなかったと書いて「対象外」にもしない（判定結果に含めない。次の実行に残る）。
- 要約は日本語1〜3文。原文の言い換えにとどめ、誇張や推測を足さない。日付・バージョン・モデル名を推測で補わない。

### 反映（SKILL.md）

- 全体で60行以内。超えるときは、優先度の低い行を details.md へ移してから足す。上限は広げない。
- 説明・背景・経緯・例は書かない。そのまま実行できる指示を、1行1項目の箇条書きで短く書く。
- 節の名前と順番：`通常の呼び出し`／`モデルの選び方`／`指示の書き方`／`指示ファイル・スキル`／`操作別の注意`／`使わないもの`。書くことがない節は作らない。最後の行は「詳細は references/details.md、最近の変更は references/changelog/。」
- 行末に出典IDを全角かっこで付ける（例：`［A-2026-11-12-1］`、`［D-claude-code-headless］`）。IDはログの項目か `references/sources.md` の根拠IDと一致させる。
- URL・「以前は」・「最近の変更」の節を書かない。変更は、該当する節の行を書き換えることで反映する。
- 新しい機能には必要なバージョンを添える（例：`〔v2.1.250以降〕`）。
- 「使わないもの」は「使わない：〜（代わりに〜）」の形。
- 料金・プラン・企業向け管理機能・他クラウドでの提供状況は、呼び方に影響しない限り書かない。
- 他社との比較や「どのAIに何を任せるか」は書かない。
- 特定のPCのモデル名・既定のオプション・パス・キーの所在は書かない（公開リポジトリのため）。

### 反映（details.md・superseded.md・sources.md）

- details.md は現時点で有効なことだけ。置き換わった内容や経緯は残さない。見出し・コードブロック・表の区切り行・「：」で終わる導入行を除く全行に出典IDを付ける。
- 置き換わった行は `references/superseded.md` の表へ、置き換わった日（YYYY-MM-DD）・置き換え後の行・根拠IDと一緒に移す（新しい順）。
- 重点ページの本文変更の項目を反映したら、その内容に当たる行の出典IDをログの項目IDに差し替え、`references/sources.md` の確認日を更新する。

## このPCだけの設定（公開しない）

`~/.ai-vendor-watch/`（環境変数 `AI_VENDOR_WATCH_HOME` で変えられる）に置く。

- `config.json`：判定・反映に使うモデル、既存の呼び出し設定の場所と検証の手順
- `mf-pending.json`：廃止・互換性変更の影響を受けるのに、移行できていない呼び出しの控え
- `config.json` の `model_watch`：見張るモデルの読み方（設定ファイルの場所と正規表現、または実行記録の置き場所）
- `model-watch.json`：モデルの見張りで知らせた控え（同じものを二度知らせないため）
- `runs.jsonl`：実行の記録
- `cache/focus/`：重点ページの前回の本文（差分を出すための控え）

既存の呼び出し設定を自動で書き換えるのは、現行の呼び出しが廃止・互換性変更の影響を受け、公式に移行先が示されていて、移行先で最小限の呼び出しが通った場合だけ。新機能や新モデルの追加では書き換えない。

## 動かし方

```
py -3 -X utf8 tools/ai-vendor-watch/run.py            # 毎日の実行
py -3 -X utf8 tools/ai-vendor-watch/collect.py --dry-run
py -3 -X utf8 tools/ai-vendor-watch/check_skill.py
```
