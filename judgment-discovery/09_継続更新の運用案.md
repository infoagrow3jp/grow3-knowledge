# I. 継続更新の運用案

作成：2026-10-25　状態：提案（何も実装していない。定期実行・自動化は新たに作っていない）

## 1. 結論

新しい研究管理の仕組みは作らない。更新の入口は、**すでに動いている2つの流れ**（研究ダイジェストと、実案件の記録）だけにする。
更新の単位は論文ではなく、この作業フォルダの**主張（03 の C1〜C20）・定義（02）・問いの文言（06）**である。論文を1本読んだら「どの主張を見直すか」を決め、見直さないなら何もしない。

## 2. 既存の資産への接続

| 既存の資産 | 状態（確認できた範囲） | 今回の方法論での使い方 |

| 研究ダイジェスト（Drive、実装指示 2026-10-24） | OpenAlex で自動収集、ライセンスが許すOA PDF を NotebookLM へ、週次ダイジェスト（2026-W43 のファイルがあることは確認。中身は読んでいない）。テーマは組織開発・組織学習／管理職・人材育成／人事制度・組織行動の3冊。研究台帳（JSONL）は別のPC上で、中身は未確認 | 新しい研究の入口。「限界・逆効果」の枠が、03 の S4（反証・競合）の更新に使える |

## 3. 更新の流れ


## 4. 更新のときに確かめること

研究から来たときも、現場から来たときも、同じ7問で見る。どれにも該当しなければ更新しない。

| # | 問い | 見る先 |
|---|---|---|
| 1 | 新しく発表された研究は、どの主張（C 番号）に関係するか | 03 |
| 2 | 既存研究の追試・反証か（例：後知恵バイアスの再現研究、ShadowBox の独立評価） | 03 の S4、01 §5 |
| 3 | レビュー論文・メタ分析で、評価が変わったか（例：CTA 訓練の効果量、事例比較の効果量） | 01 の主要15件 |
| 4 | 定義を直す必要があるか | 02 |
| 5 | 現場の方法（問いの文言・手順・時間）を変える必要があるか | 06 |
| 6 | 新しい手法が、従来より簡単か（本人の負担・準備・聞き手の技術のどれかが軽いか） | 05 |
| 7 | 現場の試行で、想定と違った点は何か | 08 §4 の判定線と記録 |

## 5. 差分の確かめ方

- この作業フォルダの改訂は git で行い、コミットの説明に「どの主張を、なぜ、何を根拠に」を1行書く。差分は `git log -p judgment-discovery/03_根拠と主張の対応.md` などで追える。
- 03・06 には変更履歴の表を置き、変更の理由と根拠を残す（変更内容だけを書かない）。
- 根拠区分を上げる（例：S5 → S3）ときは、どの文献のどの確認水準によるかを書く。下げるときも同じ。

## 6. 研究ダイジェストへの変更案（実施していない）

今回のテーマは、研究ダイジェストの3冊のどれにも入りきらない（認知・熟達研究の文献が、既存のクエリでは拾われにくい見込み）。必要なら、次のどちらかを小林さんが選ぶ。

- **案1**：「管理職・人材育成」のノートに、英語クエリを足す。例：`cognitive task analysis`、`naturalistic decision making`、`expertise elicitation`、`tacit knowledge elicitation`、`case comparison learning`。限界・逆効果の枠用に `retrospective verbal report accuracy`、`hindsight bias replication`。
- **案2**：4冊目のノート「判断と熟達」を作る（フロー1本の追加が要る）。

研究ダイジェストの実装指示は「新しい台帳や機能を足さない」方針なので、案1（クエリの追加だけ）の方が方針に合う。どちらも、実装は研究ダイジェスト側の作業として別に行う。

## 7. 更新しないと決めたこと

- 論文を集めた本数を成果にしない。
- 新しい研究が出るたびに方法を変えない。現場の手順（06）を変えるのは、現場の試行の結果か、確認水準の高い反証（本文確認以上）が出たときに限る。
- 主張台帳・問いノート・定期実行の仕組みを、この作業のために新しく作らない。
