## 2. 受け入れなかった批判と理由

- **C：障害を選択式・匿名のカードで集める（Kerr テストの代替として）**：研修で場に置く使い方は残す。ただし診断の本体にはしない。匿名の集計は特定の判断点に結びつかず、4点セットにも `info_and_authority_confirmed` にも入れられない。本体は書類との照合と、案件に結びついた1問にする
- **A：衝突場面の優先を2択カードで選ばせる**：発見の主な手段にはしない。仮想の選択は、述べた選好であり、上司に期待される答えに寄る（Aの自己批判、D）。実際に衝突が起きた案件を先に使う。カードは、認定後の教材と、責任者どうしのずれの確認に回す
- **D（第1ラウンド）：認定は検証の後に置き、承認と検証を分ける**：記述の確からしさ（予測・一致）を先に確かめる点は受け入れる。ただし、トレードオフを伴う選択ルールには、検証で決まる正解がない。責任者が目的に照らして決める規範の選択は、正当な役割である。記録の場所は `certification.reason`
- **A：simple rules は観察ポイントの層に効かない**：受け入れたうえで、扱いを分けた。観察ポイントは、ルールではなく事例の共有で渡す（4(c)）

## 4. 修正後の提案

### (a) 目的・目標・価値観・時間軸・全体最適を、判断カードと仕事マップへどう接続するか

**原則**：目的・価値観は現場社員に直接聞かない。具体の一言、実際の衝突、記録から採る。現場に渡す言葉は「必ず守ること／自分で決めてよいこと／ここからは相談すること」の3つのまま変えない。

**仕事マップ**
- **上段（段階の目的）**：「この段階で、お客様から言われて一番うれしい一言と、一番言われたくない一言は何ですか」（Cの文言）。うれしい一言が出口の基準になり、言われたくない一言が境界の候補になる
- **中段（衝突に気づくための観察ポイント）**：「この仕事を急いで（または丁寧にやりすぎて）、あとで別の工程やほかのお客様が困ったこと、最近ありましたか」。時間軸と全体最適を、具体の出来事で聞く問いである。答えは観察ポイントの候補になる（「受ける前に◯◯を見る」）
- **下段（こだわり）**：「このこだわりを守れなかった日、何が起きましたか」。こだわりは語りなので、起きた出来事と記録で照合する

**判断カード（モノサシ1件）**
- 必須の添え書きは、実際に衝突があった場合だけ「ぶつかったら、どちらを取るか」
- その中身は責任者が決め、`certification.reason` に「何のために、何を捨てて」を書く
- 現場社員への確認の問いは、「前に、◯◯と◯◯が両方は無理だったとき、実際どっちにしましたか」（過去の出来事の想起）
- 時間軸（「1年続けたら、お客様全体にとってどうか」）は、責任者が認定するときの口頭の確認とする（C・Dと一致）
- 現場社員には聞かない

**判例を回す**
- 朝礼・週次で1分：「昨日、◯◯と◯◯で迷って、こっちを取った件」
- 管理職が、そのときの判断を記録する。何を捨てたか、何のためか。結果はまだ書かない
- うまくいかなかった判例も同じ形で残す

### (b) 判断できない・行動できないときの診断の型

本人の言語化に頼らず、3問で見る。面談者が持つのはこの3問だけにする。

**問1　対応が一貫しているか（基準の有無）**
- 似た2件（本人の「すんなり／手こずった」、または記録から拾った2件）で、本人の対応が同じかを見る
- 違えば、2件の差のうち本人が口にしたものを1つ戻して、「それだけ同じだったら、同じことをしていましたか」（はい／いいえ／分からない）と聞く
- 一貫していなければ、基準が無いか、届いていない
- 本人と責任者で対応が違えば、見え方のずれとして、事例の比較へ回す

**問2　書類と記録で、ぶつかるものがあるか（仕組み）**
- 面談者が、モノサシの候補と次の書類を並べる
  - 評価表・目標設定表・歩合や手当の規程（DOCUMENTED）
  - 権限規程・決裁の運用
  - 受け渡しの記録（その情報が届いていたか）
- 本人の負担はゼロである
- 本人には、過去の出来事の想起だけを聞く：「前にそうしたとき、誰かに何か言われましたか」（言われた／言われなかった／覚えていない）
- 責任者には直接聞く：「この基準どおりにすると、今の評価や数字の上で、この人は得をしますか、損をしますか」

**問3　衝突を、会社が決めているか（規範）**
- 2つの正しさがぶつかっていて、責任者がまだ決めていなければ、基準づくりの問題ではない。経営の選択の問題として社長へ返す
- 決めるまでの間は、4点セットでその判断点を一時的に相談線へ下げ、確認時点を置く

**結果の扱い**
- 問1で一貫していない → 育成用途のモノサシ（暫定と明示）
- 問2でぶつかる → 07の `info_and_authority_confirmed` が満たされないので、評価項目にしない。制度・権限を直す材料として経営へ返す
- 問3で決まっていない → 経営判断へ返す

この型は、06の③（ズレた場所）を置き換えるものではない。③で「情報がなかった」と出たら、問2の受け渡しの記録で確かめる（D）。

**社長が熟練者で、評価者でもある会社**（C）：問2の書類照合を、Grow3が社長へ示す。結論ではなく選択肢として示す（支援OS原則1）。方法だけで解ける問題ではないことを、先に伝える。

### (c) 何を標準化し、何を事例で共有し、何を裁量に残すかの判定

判断点ごとに、次の4問を順に当てる。統制深度の3段階に「事例で共有」を内部の区分として重ねる。現場の3語は変えない。

| 問い | はいなら | 統制深度 |
|---|---|---|
| 1. 失敗の非対称性が大きく、正解が外から決まるか（法令・安全・金銭） | **標準化**（手順・チェック）。熟練者からは採らない。規程から書く | ① |
| 2. 2つの正しさがぶつかり、会社として向きを決める必要があるか | **標準化（選択ルール）**。責任者が決め、目的を理由として書く。ガードレールとして渡す | ② |
| 3. 何を見るかで結果が分かれるが、ルールにすると伝わらないか（見分け・予期） | **事例で共有**。判例・写真・2件比較で渡す。観察ポイントは候補として、暫定と明示する | ②〜③ |
| 4. 規則性とフィードバックがあり、やり方の違いが結果を壊さないか | **裁量**。事後の振り返り（判例の記録と予測の当たり外れ）だけを残す | ③ |

- 規則性もフィードバックもない判断（長期の顧客関係、採用など）は、4に入れない。2で責任者が向きを決め、記録して後から照合する（A・Dと一致）
- 対話を続けるか見切るかという、顧客との探索の判断には、撤退条件と確認時点を4点セットで前もって置く
