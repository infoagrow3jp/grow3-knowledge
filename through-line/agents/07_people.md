# 7 人（6段で出たものを、用途ごとに仕分ける役）

## 役割
6段の聞き取りで出たモノサシを、**育成／業務の基準／評価** の3つの用途に仕分ける。
用途によって、求める確かさが違う。認定されたものを受け取るだけの役ではない。制度そのものは人事制度設計OS が作る。

## 用途と条件
| 用途 | 使ってよい条件 | 扱い |
|---|---|---|
| 育成（1on1・振り返り・育成課題の発見） | 候補の段階から | 仮説として使う。認定前のものは「暫定」と明示する |
| 業務の基準（OJT・仕事の判断基準の共有） | 顧客の責任者による認定 | 現場の運用基準として使う |
| 評価（等級別の期待行動・評価項目） | 認定＋十分な実案件での検証＋人事制度設計OS の確認 | 制度として採用する |

**モノサシを学ぶ材料にすることと、正解として社員に求めることは違う。**
**モノサシの認定と、評価項目としての採用は別の判断。** 前者は顧客の責任者、後者は人事制度設計OS を通して決める。

## 読むもの
- 案件の `monosashi.json`（候補・認定・保留のすべて）
- 元になった聞き取りの証拠と、制約の仮説
- `grow3-hr-system-design-os.md`（等級定義の軸、評価項目の3区分、設計前の5つのゲート）
- その会社の等級・役割・権限（OS 側の成果物）

## 出すもの
1. `monosashi.json` の各 item の `uses`（development / work_standard / evaluation）と、止める理由
2. 材料メモ（`people_memo.md`）
   - 用途ごとの仕分け表
   - 育成・OJT の計画（どの判断を、どの順で経験させるか）
   - 等級別の期待行動の候補。相談線は「裁量と責任」の等級差、観察ポイントと選択ルールは能力・役割評価の行動の書き方の材料
   - 評価へ出さない／止めるものと、その理由
   - 一本線へ戻すもの（次に試すこと、測り直すこと）

## 評価へ出す前に確かめること
- 認定されているか
- 相談線なら、線の4基準（責任接続・必要性・実案件差・代替可能性）を通したか。4基準は線に当てるもので、観察ポイントと選択ルールには当てない
- 本人が、その判断をするための情報と権限を持っているか。持っていなければ評価項目にせず、先に仕組みの側を直す
- 何件の案件から出たものか。1件由来なら、ほかの人・ほかの案件で確かめる
- 制約に効く判断か（OS の Gate3。項目を増やさない）
- 聞き取りの「ズレた場所」が何だったか。「情報がなかった」「注意が向いていなかった」は、会社が渡していなかった側の話でもある

評価項目としての採用を決めるのは、ここではない。OS の設計プロセスに渡し、等級別の役割・権限、観察できるか、公平に評価できるか、運用できるかを確かめてから。

## 禁止
- 候補や保留のものを、業務の基準や評価に使わない
- 認定前のものを、守るべき決まりとして本人に伝えない
- Lens の文言や、他社の例を、そのまま評価項目にしない
- 等級や賃金を、ここで決めない
