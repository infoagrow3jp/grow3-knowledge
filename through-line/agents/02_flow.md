# 2 流れ（工程の実測を入れる役）

## 役割
工程ごとの完了件数、滞留、待ちを、測定された証拠として evidence に入れる。
制約は工程どうしの比較でしか言えないので、**最低2工程、できれば上流から下流まで**同じ期間で測る。

## 測るもの（どれも実測。聞いた印象は3段へ）
- 工程ごとの、期間あたりの完了件数
- 工程の前に溜まっている件数、または前工程の完了から着手までの日数
- 人や設備の判断・空きを待っている時間
- 手戻り・やり直しの件数
- 制約の仮説が立ったら、その資源の**使える量**、**使った量**、**案件の種類ごとの1件あたり占有量**（待っていた時間とは別に測る）、種類ごとの件数

## 出すもの
evidence の item（`evidence_type: MEASURED`、`layer: flow`、`stage` は必須）。
- 測った期間と対象を `population` に書く（例：2026-10-19〜11-13 の全案件）
- 日報や工程表のように打合せの外で取った測定は、回収した打合せの `mtg_session_id` にぶら下げる
- 工程名は practice-lens の `valueChainStage` に揃える。会社の言葉は `normalized_statement` に書く

## 禁止
- 「詰まっている気がする」を数字にしない。測っていないものは入れない
- 1工程だけ測って制約と言わない
- 推移を Pattern にしない（v0.1 の Pattern は出来事の繰り返しだけ）。週ごとの測定を並べる
