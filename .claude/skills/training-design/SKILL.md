# training-design：研修設計の読込順序と実行手順

## このスキルの役割（複製禁止）

- 本スキルは研修設計の正本ではない。**正本と関連資料を正しい順序で読むための
  ルーター兼実行手順**である。
- **設計思想・研修の定義・学習原則の正本**：`grow3-training-design-os.md`
- **理論・フレームの定義の正本**：`grow3-frameworks.md`
- 正本の本文（設計哲学・学習の最小機構・ワークの型・採点軸等）を本ファイルへ
  再掲しない。書き写した瞬間に、正本の改訂とスキルの記載がズレる二重管理
  リスクが生じるため。判断原則を確認する必要が生じたら、その場で正本を
  読みに行く。

## 必須読込順序

研修の設計・レビュー・改善・成果物設計を行うときは、次の順序で読む。
**対象ファイルが読めない場合は、一般論で補完せず停止して報告する。**

1. `grow3-training-design-os.md` を必ず読む（設計思想・定義・学習原則・
   設計プロセス・構造の型・品質基準のすべての正本）。
2. 使用する理論・フレームの定義が必要な場合は `grow3-frameworks.md` を読む
   （正本内の `[→F:○○]` 参照の解決先）。
3. 採点・レビューを行う場合は、下記「採点資産の振り分け」に従って実在する
   採点資産を読む。
4. コーチング・1on1・部下育成など該当テーマでは `grow3-coaching-training-os.md`
   を読む（テーマ固有の哲学・定義・型）。
5. テンプレートへ実装する場合は `grow3-training-design-implementation-templates.md`
   を読む（設計ヒアリング質問・標準化の仕分け等の実装帳票）。
6. Grow3共通の判断（第0原則・指示の優先順位・採点の発動条件等）は
   `grow3-judgment` スキルの指示を常に優先する。設計・レビューに先立ち、
   `grow3-judgment` により依頼対象と研修タイプの判定を行う。

## 採点資産の振り分け（採点・レビュー時）

1. まず `.claude/skills/grow3-judgment/references/training-review.md` を読み、
   研修タイプを判定する（軸を機械的に適用しない）。
2. **参加型・行動変容型**の場合：`.claude/skills/coaching-training/SKILL.md`
   の参加型研修3軸を使う。
3. **知識習得型・短時間講義型**の場合：`training-review.md` の一般5軸を使う。
4. 案件固有の採点軸が指定されている場合は、それを追加して使う。

なお `coaching-training/SKILL.md` には二つの役割がある。混同しない。

- **採点時**：参加型研修の3軸ルーブリックとして参照する。
- **コーチング研修の設計時**：テーマ固有の設計原則への入口として参照する
  （中身の正本は `grow3-coaching-training-os.md`）。

## 実行手順

1. **依頼範囲と維持対象を分ける**（`grow3-judgment` 第0原則）。何を変える依頼か、
   何を維持する依頼かを着手前に分け、依頼されていない箇所は変更しない。
2. **最新版を確認する**：最新版成果物・案件固有資料（Decision Log・Run Book・
   確定済みスライド等）・正本OSを確認し、どれが正かを特定する。
3. **研修タイプと目的を判定する**（`grow3-judgment` の判定に従う）。
4. **設計・確認の順序**：ゴール → 一本線（1メッセージ）→ 構造 → ワーク →
   時間 → 成果物 の順で進める。各段の判断基準は正本
   `grow3-training-design-os.md` の該当部（設計の思想・設計プロセス・構造の型・
   テーマ別マッピング・ファシリテーションの型）をその場で読む。
5. **実装後の検証**：正本OS第6部に定められた段階判定と品質基準で検証する
   （基準の本文はここに書かない。第6部を読む）。
6. **未確認事項を勝手に確定しない**。不足情報は「結論が変わるか」で二分し、
   変わるなら着手前に質問する。
7. **既存の確定スライド・ワーク・進行を、改善目的で無断変更しない**。改善案は
   本文へ反映せず、提案として分けて添える。

## 使い分け（どこに何があるか）

| 知りたいこと | 読む場所 |
|---|---|
| 理論・フレームの定義 | `grow3-frameworks.md` |
| 研修設計の判断原則（定義・思想・学習機構・プロセス・型・品質基準） | `grow3-training-design-os.md` |
| 採点軸 | 上記「採点資産の振り分け」（training-review.md ＋ coaching-training） |
| テーマ固有OS（コーチング・1on1・部下育成） | `grow3-coaching-training-os.md` |
| 実装帳票（ヒアリング質問・仕分け表・テンプレート） | `grow3-training-design-implementation-templates.md` |
| 案件固有の確定事項 | 最新版の案件ファイル・Decision Log・Run Book 等 |

## 停止条件

次の場合は推測で進めず、停止して報告する。

- 正本または最新版が特定できない。
- ユーザーの依頼と確定済み設計が衝突する。
- 正本の変更を伴うが、人間承認がない。
- 実施済みの事実と仮説を区別できない。
- 依頼範囲外の構造変更が必要になる。

## 成果物への接続と完了時の検証

- 標準成果物セット（PPTX／TS／ファシリテーターガイド／ワークシート／
  振り返りシート等）の構成と品質基準は、正本OS第6部を読む。
- 完了時は、①依頼範囲外を変更していないこと ②TS検算等の正本OSに定める
  検算・品質基準を満たすこと ③未確認事項が【要確認】として明示されている
  ことを確認してから納品する。日本語Office成果物の生成時は
  `jp-office-layout` スキルの制約に従う。
